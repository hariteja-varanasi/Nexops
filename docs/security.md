# Security

## This repository is public

That changes the threat model in one specific way: **every value written in
these files is known to everyone.** The placeholders are not weak secrets, they
are published secrets. A `JWT_SECRET` visible on GitHub lets anyone mint a token
your server will accept as a valid admin session.

Three things follow from that.

**The backend refuses to start in production with a published secret.**
`backend/src/config/env.js` rejects anything matching a placeholder shape
(`CHANGE_ME…`, `replace_with…`, `changeme`, and so on) or shorter than 32
characters, and refuses the documented `admin123` password while seeding is
enabled. Outside production these are warnings, so a training cluster still
boots with the demo credentials.

```
Error: Refusing to start in production with insecure configuration:
  - JWT_SECRET is still one of the placeholder values from this repository.
```

**Install the pre-commit hook before you start working.**

```bash
git config core.hooksPath .githooks
```

It blocks `.pem`, `.key`, `kubeconfig`, `.env`, `.tfvars` and `.tfstate` files,
and scans staged diffs for AWS keys, GitHub and Docker Hub tokens, Slack tokens,
private key blocks and signed JWTs. It deliberately allows the repository's own
`CHANGE_ME` placeholders and Kubernetes `secretKeyRef` references, so it does
not cry wolf.

**A leaked secret cannot be un-leaked by deleting it.** It stays in the history,
in every clone and in every fork, and GitHub keeps unreferenced objects
reachable for a while. If it happens: rotate the credential first, rewrite
history second. Rotation is the fix; history rewriting is cleanup.

```bash
# Rotate immediately — this is the part that actually matters
# Then, optionally:
git filter-repo --invert-paths --path path/to/leaked-file
```

## What is never committed

```
.env                    generated by setup.sh, git-ignored
jenkins/.env            generated, git-ignored
terraform.tfvars        git-ignored
*.pem  *.key            git-ignored
kubeconfig              git-ignored
```

`.env.example` is committed. `.env` is not. Every secret is generated at setup
time with `openssl rand`, never shipped in the repository.

The two placeholder files that *are* committed —
`kubernetes/base/config/secret.yaml` and the `secrets:` block in
`helm/nexops/values.yaml` — carry `CHANGE_ME` values and a comment explaining
that they exist to show the shape, not to be used.

## Secrets in Kubernetes

Kubernetes Secrets are **base64, not encryption**:

```bash
kubectl -n nexops-dev get secret nexops-secrets -o jsonpath='{.data.JWT_SECRET}' | base64 -d
```

Anyone with `get secret` in the namespace can read them. That is why:

- `setup.sh` creates the Secret imperatively from generated values
- `helm/nexops/values-prod.yaml` sets `createSecret: false` and expects an
  out-of-band Secret
- For GitOps, encrypt before committing:

```bash
kubeseal --format yaml < secret.yaml > sealed-secret.yaml   # safe to commit
# or
sops --encrypt --age <public-key> secret.yaml > secret.enc.yaml
```

## Container hardening

Both images:

```yaml
securityContext:
  runAsNonRoot: true
  allowPrivilegeEscalation: false
  readOnlyRootFilesystem: true          # backend and redis
  capabilities: { drop: ["ALL"] }
```

`readOnlyRootFilesystem` is why the frontend mounts three `emptyDir` volumes —
NGINX needs to write its cache, pid and the envsubst output, and nothing else.

The frontend runs as uid 101, which cannot bind port 80 at all. It listens on
8080 and the Service maps 80 → 8080. The inability to bind a privileged port is
the point, not an inconvenience.

## Application security

| Control | Where |
|---|---|
| bcrypt password hashing | `userService.js`, configurable rounds |
| Constant-time login | Compares against a dummy hash when the user is missing, so response time does not reveal whether a username exists |
| JWT with issuer check | `middleware/auth.js` |
| Role gate on every write | `authorize()` on each mutating route |
| Rate limiting on login | 20 attempts per 15 minutes per IP |
| Input validation | zod schemas on every body and query |
| Parameterised SQL | `pg` placeholders throughout — no string concatenation anywhere |
| Secret redaction in logs | pino `redact` on `authorization`, `password`, `token` |
| Security headers | helmet |
| No stack traces in production | `errorHandler.js` includes them only when `NODE_ENV !== 'production'` |

The backend also refuses to start in production with the default JWT secret:

```js
if (env.nodeEnv === 'production' && env.jwtSecret === 'change-me-in-every-environment') {
  throw new Error('JWT_SECRET must be set to a unique value when NODE_ENV=production');
}
```

Failing to boot is better than booting insecurely.

## Network

NetworkPolicies (production overlay) default-deny ingress, then allow:

- ingress-nginx → frontend and backend
- backend → PostgreSQL and Redis
- monitoring namespace → backend:4000 for scraping

Verify: exec into the frontend pod and `nc -zv nexops-postgres 5432`. It hangs.

**Important caveat:** kind's default CNI accepts NetworkPolicy objects and
silently ignores them. To actually enforce them, set `disableDefaultCNI: true`
in `kind-config.yaml` and install Calico. Left enabled by default so the cluster
comes up without extra steps — but know that the policies are documentation
until you make that change.

## Supply chain

| Stage | Control |
|---|---|
| Dependencies | `npm ci` from a committed lockfile |
| Base images | Pinned minor versions (`node:22-alpine`, `nginx:1.27-alpine`) |
| Image scan | Trivy fails on fixable HIGH/CRITICAL |
| Code scan | SonarQube quality gate with `abortPipeline: true` |
| Binary downloads | `setup-ec2.sh` verifies SHA256 for kubectl and Helm |
| Registry auth | `--password-stdin`, never `-p` on the command line |

## AWS

- IMDSv2 required (`http_tokens: required`) — v1 is reachable from any process
  on the box, including a compromised container, and hands out instance
  credentials
- Root EBS volume encrypted
- SSH and every admin port restricted to `allowed_ssh_cidr`, with variable
  validation that **rejects `0.0.0.0/0`** so nobody opens port 22 to the
  internet by accident
- No AWS credentials in any file — environment, `~/.aws/credentials`, or an
  instance profile

## Known trade-offs

Honest list of what this project does for teaching convenience that you should
not copy to production:

1. **`admin`/`admin123` seeded by default.** Deliberate, so the demo works out
   of the box. Change `SEED_ADMIN_PASSWORD` before any shared environment.
2. **Jenkins mounts the host Docker socket.** Grants the container root on the
   host. Use rootless agents or Kaniko at work.
3. **Self-signed Argo CD certificate.** Fine behind a port-forward; use a real
   certificate if you expose it.
4. **No TLS on the Ingress by default.** `ingress.tls.enabled` exists; wire up
   cert-manager for a real certificate.
5. **Single PostgreSQL replica, no backups.** A training database. Real ones
   need replication and tested restores.
6. **kind's CNI does not enforce NetworkPolicy.** See above.

## Public-repository checklist

Before the first push, and before each one after:

```bash
# The hook is installed
git config --get core.hooksPath          # → .githooks

# Nothing sensitive is tracked
git ls-files | grep -E '\.env$|\.pem$|\.key$|tfvars$|tfstate' # → empty

# No credential shapes anywhere in the history
git log -p | grep -nE 'AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{36}|dckr_pat_' | head

# The images you publish are public too. Confirm no secret was baked in:
docker run --rm nexops-backend:local env | grep -iE 'secret|password'   # → empty
```

The Docker Hub images are public as well. Nothing secret is baked into them —
every credential arrives at runtime from the environment — but it is worth
confirming rather than assuming.

## Before exposing this to anyone

```bash
# Rotate everything
openssl rand -hex 32                     # JWT_SECRET
openssl rand -base64 24                  # POSTGRES_PASSWORD, SEED_ADMIN_PASSWORD

# Lock down the security group
terraform apply -var="allowed_ssh_cidr=$(curl -s ifconfig.me)/32"

# Confirm nothing sensitive is tracked
git ls-files | grep -E '\.env$|\.pem$|\.key$|tfvars$'     # must return nothing
git log -p | grep -iE 'password|secret|token' | grep -v CHANGE_ME | head
```
